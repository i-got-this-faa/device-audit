## Checks and reproduction

The Unix-oriented Makefile needs a POSIX shell and `make`, which this session
did not have. The equivalent native commands below were run from the repository
root. Put the pinned Go executable and a Python interpreter on `PATH` first.
The Go 1.27.1 Windows amd64 ZIP was checked against the official download
metadata, SHA-256
`a3911b5e0e1b1053f25ed0675f4c1c6aad1e2bfcf253df2b9be4caabd2edd95d`.
The missing C compiler was installed with
`winget install --id BrechtSanders.WinLibs.POSIX.UCRT --exact` (package version
16.2.0-14.0.0-r1; winget verified its installer hash). Refresh the process `PATH`
from the user environment or start a new shell after installation.

```powershell
go version
python --version
go vet ./...
go test ./...
gofmt -l (git ls-files '*.go')  # must produce no filenames
New-Item -ItemType Directory -Force bin | Out-Null
go build -o bin/controller.exe ./apps/controller
go build -o bin/endpoint-agent.exe ./apps/endpoint-agent
$env:PYTHONPATH = 'models/src'
python -m unittest discover -s models/tests -v
python tools/demo.py
$env:GOOS = 'windows'; $env:GOARCH = 'amd64'
go build -o bin/endpoint-agent-windows.exe ./apps/endpoint-agent
$env:GOOS = 'darwin'; $env:GOARCH = 'arm64'
go build -o bin/endpoint-agent-darwin ./apps/endpoint-agent
Remove-Item Env:GOOS, Env:GOARCH
$env:CGO_ENABLED = '1'
gcc --version
go test -race ./...
```

The demo bound the controller to a dynamically selected literal loopback
address and terminated it afterward. Endpoint telemetry remained `source=fixture`
with hardcoded CPU/memory values; the controller used in-memory storage.

Git for Windows used `core.autocrlf=true`, which checked Go files out as CRLF
and made `gofmt -l` report every Go file. `.gitattributes` now pins `*.go` to LF.
The repository Go source content is unchanged. Existing checkouts can refresh
clean Go files or run `gofmt -w` before repeating the format check.

## Read-only availability observations

Standard-user CIM queries could read CPU performance, memory/disk capacity,
display adapter metadata and a battery object. `Get-WinEvent -ListLog System`
and `-ListLog Application` could read enabled log metadata; event contents were
not collected. These are source-availability observations, not implemented
endpoint collectors, accuracy tests, or measured collection overhead.

`Get-CimInstance -Namespace root/wmi -ClassName MSAcpi_ThermalZoneTemperature`
returned **Access denied**. Temperature therefore remains unavailable in this
permission context. No temperature value, elevated-access success or GPU
utilization measurement is inferred from adapter metadata.
